# Local prepared-byte publication boundary — design and remaining qualification

Current selected local publication/readback and technical verification are implemented; see07-02-PUBLICATION-PARTIAL for tested scope. This earlier design describes the protocol; its remaining test matrix is not all executed evidence. No queue loop, commercial authority or provider qualification follows. Country/tax remains pending.

## One selected claim, three boundaries

1. Outside any database transaction require exact BoundPreparedArchive type and attest its root descriptor/path/marker. In a short owned durable transaction run locked_claim(claim_id, private_token). Compare bound destination UUID/device/inode/manifest/profile to the attested LocalDestination; compare exact retained envelope identity/bytes/hash/length and source. Copy only the bounded prepared bytes into internal memory. Return no payload/token/path in ordinary output. Commit all locks before any adapter I/O. A prior standalone inspection result is insufficient.
2. With no database transaction call archive.publish(envelope.id, exact_bytes), validate the exact PreparedReceipt using manifest and independently constructed expected identity/hash/size/classification, reopen/readback using recover and compare exact bytes. Reattest the same physical destination outside transactions. Never treat a successful write call or prepared receipt as completed domain/financial evidence. Never choose a new key/root or delete retained bytes on failure, uncertainty, lease expiry or revocation. Keep errors fixed and private-data-free.
3. In a new owned short transaction run locked_claim again. Validate current authorization/source/owner/credential/grants/revocation, latest lease token/generation/deadline, exact destination and retained payload against the earlier expected bytes/receipt. Only then append a technical local prepared-verification record. Publication after lease loss can leave retained bytes; it cannot receive a successful verification record. Physical root changes after the last attestation cannot be promised impossible; define the acknowledgement window honestly and do not infer provider durability.

## Proposed retained verification record and retries

Add one protected local prepared-verification record per intent, retaining exact envelope/destination, claim/authorization generation, receipt evidence UUID/hash/size and database observation time. Require fixed local-synthetic/prepared classification and false retention/effects flags. No public private-byte/receipt export. Preserve authorization and claim histories. No offer, acceptance, bank dispatch, document issue, licence delivery, support credit or completed support work follows from this record.

Define exact successful replay before exposing any result: a matching retained record may return historical safe metadata only after current exact caller/claim authority is resolved. Historical technical verification is not fresh active authority; do not renew leases to acknowledge it. A completed intent must not acquire replacement publications or silently rewrite original attribution. Current capture/binding retries must continue preserving the same intent/fact; design terminal semantics explicitly rather than widening states without tests. Only a later deliberate read with current exact permissions may recover private bytes.

If acknowledgement is lost after filesystem publication but before database verification, retry the same envelope identity/bytes at the same root under an eligible live/reclaimed lease. Adapter exact retry/readback reconciles files. If acknowledgement is lost after the verification transaction commits, reconcile its unique record without creating new effects or losing original attribution. Database errors must leave physical evidence retained; do not mark an uncertain transaction successful without reading the committed record. A missing/corrupt/mismatched blob/receipt/root fails closed. No automatic paid/provider fallback, remote retention or off-host custody inference.

These are proposed checks, not executed evidence. Independent process/outage/off-host/provider/production tests remain separate gates.
