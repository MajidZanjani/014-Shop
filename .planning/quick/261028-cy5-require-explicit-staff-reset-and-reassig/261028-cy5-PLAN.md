<design_critique>
Current quarantine rotates generations and invalidates sessions but preserves enabled credentials and seven staff grant tables. An older snapshot can therefore retain revoked assignments. Existing local_staff reset/revoke already clears all seven types; extract one shared internal transaction-only helper rather than create a competing approval/manifest system. Only a new quarantine whose request_id equals configured LOCAL_RESTORE_ID disables credentials and clears all assignments. No matching setting means the ordinary temporary-hold behavior remains. Replay returns immutable prior counts without repeating removals. Existing generation fencing invalidates prepared authorizations, and existing private tokens remain session-bound. Actual post-point customer/resource/MFA reconciliation and off-host custody remain pending. No external API integration or new dependency.
</design_critique>
