## Task1 — Durable admission fence and honest drain state

Add constrained local effect admissions, with one-way database-protected exit records. Admission locks the existing AccessEpoch singleton in a short durable transaction, checks the current hold and commits before any effect. No row/advisory lock or transaction spans adapter execution. Quarantine uses the same singleton lock: after its commit no new admission can start. Work admitted earlier may finish and is reported as unfinished until its exit commits. A missing exit (including process loss or exit-record failure) never expires or authorizes replay. Synthetic release refuses while any admission remains unfinished. Read-only drain inspection and exact quarantine/release retries report current state without claiming actual recovery qualification or provider reconciliation.

Wrap the existing worker execution, probe/statement/notification claims, statement capture/notification processing, payment/finance dispatch and mutating synthetic-bank entry points. Worker calls during hold return their existing idle/no-claim result; dispatch/mutation raises a fixed domain error before claim/provider effects. A nested adapter admission rechecks the hold, so a quarantine between an archived one-way claim and a provider call leaves that claim uncertain and lookup-only. Do not apply a blanket hold to synthetic_bank.guard(), lookup(), lookup_mutation(), manual attempt reconciliation, inspection or ordinary completion bookkeeping. Keep existing scopes, archive/readback, lease/token/attempt bounds and finance/MFA controls.

## Pre-execution critique

A single pre-dispatch flag read is insufficient. Holding a transaction/advisory lock across provider I/O violates the existing no-lock adapter contract. Durable admissions solve ordering without that lock; they intentionally cannot cancel work already admitted. Synthetic release can only establish that tracked local call scopes exited, not that money, grants, external credentials or post-restore state are reconciled. The existing in-memory capture/code files remain synthetic local access fixtures, not an SMTP adapter. Actual startup restore-mode/traffic/egress isolation and full recovery remain gated.
