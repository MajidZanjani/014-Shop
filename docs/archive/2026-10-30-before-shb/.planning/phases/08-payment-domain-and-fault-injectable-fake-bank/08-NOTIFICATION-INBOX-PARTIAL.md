## Implemented behavior

`payments/notifications.py` admits only explicit UUID hints for an exact known uncertain/observed attempt whose original archive recovers. A prepared, cancelled, expired or unknown attempt cannot be dispatched by a hint. Hint identity is globally unique, bound to the original attempt payload hash; same-identity same-scope retries recover one immutable intent, conflicting scope rejects. No status, amount, currency, merchant, credentials or arbitrary payload can be supplied. Each attempt has a1000-hint cap. Hint/archive readback and pending-delivery insertion commit atomically. The management command `local_bank_notification enqueue|inspect --notification ... [--attempt ...]` runs only in local/synthetic fake-bank mode against the configured existing private checkout archive, never initializes/adopts a root, and prints only closed safe state/flag fields without identifiers/amounts/paths/bodies.

The existing single `run_worker` lifecycle checks statement captures, then notification hints, then disposable probes. Short PostgreSQL `SKIP LOCKED` claims use fresh tokens,1–60-second leases and1–5 attempts (default3). Exhausted expired claims become held. Claim commits before provider lookup; no attempt/delivery lock or DB transaction spans the typed fake-bank read. Archive intent and original attempt are verified; only exact typed merchant/reference/currency/amount/status correlation can reach commit. Missing lookup records a checked miss and leaves uncertainty intact; a later new hint can request another lookup. No hint authorizes a second `start`, dispatch, grant or payment confirmation.

Canonical lookup evidence archives/read-backs before the final transaction. Under attempt then delivery locks, current lease/token and original scope are rechecked; immutable result, validated attempt observation and checked acknowledgement commit together. `attempts._apply_locked` factors the same prior `_record` matching/conflict rules without adapter I/O; existing dispatch/reconcile paths retain their behavior. A stale worker can prepare local bytes/read the fake provider, but cannot commit an observation. A DB failure leaves prepared bytes only; a new process can recover the same result identity. A lost completion response sees already checked state, with no second lookup/start. Differing normalized evidence at the same prepared result identity holds rather than overwriting it.

SQL triggers forbid hint/result update/delete. Mutable delivery rows constrain state/lease/token/attempt bounds. Inspection locks a consistent attempt/delivery snapshot, verifies original archives and normalized result/current observation consistency, and always reports actual callbacks, dispatch authorization and financial confirmation false. No customer/staff browser interface is added in this slice; existing resource-authorized payment status reflects the verified synthetic observation, and fulfilment remains separately idempotent/explicit.
